which fail by design (issue #48, decision 70 — a mode the port has not
converted must not report success).

## 3. Differential harness contract (issue #43 §4)

- **Two lanes per scenario:** `env` (candidate + `defaults.env` vs reference + the
  same `defaults.env`) and `toml` (candidate + `defaults.toml` vs reference + an
  equivalent `defaults.env`). A mutating scenario uses up to four independent
  fixtures.
- **Separated per implementation per lane:** `HOME`, project, registry, and a
  distinct workspace name (each `run_one` passes the scenario a `<impl>-<lane>`
  tag; the qdrant collection name is `workspace_<ws>`, so it separates with the
  workspace). No implementation runs over state another run touched.
- **Compared separately:** exit code · stdout (raw, normalized — order and
  whitespace **not** normalized) · stderr · structural JSON (types, conditional
  fields, key sets — a second gate on top of the raw stdout diff, order-insensitive) ·
  file manifest (relative path, type, octal mode, hash of normalized content;
  `.git` excluded) · declared external effects (`scenario_observe_effects`; the
  hermetic seed scenarios declare none — stub-backed effect scenarios arrive
  with the integration slices, issue #42).
- **Normalized only:** the canonical fixture root → `{FIXTURE}`, the canonical
  home root → `{HOME}`, the per-run workspace tag → `{TAG}`, and a **format-gated**
  `meta.generated_at` → `{GENERATED_AT}` (a value that fails the ISO-8601-`Z`
  check is left as-is and shows as a difference). Not order, not whitespace, not
  exit, not health classification, not the spelling of a registered path.
- **Known divergences are positive scenarios** with an exact local diff, never a
  global ignore list (§5). A scenario declares one with
  `scenario_expected_divergence` (echo the dimensions allowed — **and
  required** — to differ). A dimension outside the list that differs still
  fails; a listed dimension that does *not* differ also fails (a stale
  divergence claim). Reference-vs-reference, such a scenario is
  `unimplemented` — it needs a real candidate to have anything to diverge.
- A scenario may run under a **non-default PATH** via `scenario_path_override`
  — used only by `runtime-gate`, to reach the machine's sub-3.11
  `/usr/bin/python3`. Still hermetic: no grepai / gitnexus / ollama / node /
  claude / codex.
- `PYTHONDONTWRITEBYTECODE=1` is set for every run so a Python candidate's
  bytecode caches never enter the file manifest.
- **`toml` lane with no TOML-consuming candidate reports `unimplemented`** — not
  skip, not pass (issue #46 §3).

These run the reference against **itself** over separated fixtures. They prove
the harness mechanics — fixture isolation, every comparison dimension, the
declared normalizations — **not** any port. As of issue #50 a candidate exists
(`agent-code-intel.py`); `cli-version` and `cli-unknown-flag` now also run green
against it and carry their parser rows below.

| `cli-unknown-flag` | `--definitely-not-a-flag` | **exit 1**, stderr (`[ERROR: …]`) — proves a failing tool's exit code and stderr are captured, not just the happy path | zero diff |
| `status-json-drift` | `--status --json` over a registered project, no stack | structural JSON + raw stdout, `generated_at` gating, file manifest (read-only) | zero diff |

(`script_version`); a candidate that swallows the unknown-flag error fails
`cli-unknown-flag` on the `exit` dimension. The comparator is not a no-op.
