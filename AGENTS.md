# GitNexus — Code Intelligence

This project is indexed by GitNexus as **agent-code-intel** (1366 symbols, 2875 relationships, 19 execution flows). Use the GitNexus MCP tools to understand code, assess impact, and navigate safely.

> If any GitNexus tool warns the index is stale, run `npx gitnexus analyze` in terminal first.

## Always Do

- **MUST run impact analysis before editing any symbol.** Before modifying a function, class, or method, run `gitnexus_impact({target: "symbolName", direction: "upstream"})` and report the blast radius (direct callers, affected processes, risk level) to the user.
- **MUST run `gitnexus_detect_changes()` before committing** to verify your changes only affect expected symbols and execution flows.
- **MUST warn the user** if impact analysis returns HIGH or CRITICAL risk before proceeding with edits.
- When exploring unfamiliar code, use `gitnexus_query({query: "concept"})` to find execution flows instead of grepping. It returns process-grouped results ranked by relevance.
- When you need full context on a specific symbol — callers, callees, which execution flows it participates in — use `gitnexus_context({name: "symbolName"})`.

## Never Do

- NEVER edit a function, class, or method without first running `gitnexus_impact` on it.
- NEVER ignore HIGH or CRITICAL risk warnings from impact analysis.
- NEVER rename symbols with find-and-replace — use `gitnexus_rename` which understands the call graph.
- NEVER commit changes without running `gitnexus_detect_changes()` to check affected scope.

## Code intelligence: GrepAI, GitNexus, grep

This project is wired into two indexes. Both exist to save work, not to be
performed as ritual — reach for the one that answers the question with the
least effort.

- **GitNexus** (MCP: `gitnexus_query`, `gitnexus_context`, `gitnexus_impact`,
  `gitnexus_rename`, `gitnexus_detect_changes`) — the knowledge graph. Use it
  for graph-level questions: blast radius before an edit, execution flows,
  cross-file impact, call-graph-aware renames, and `detect_changes` before a
  commit that touches code.
- **GrepAI** (MCP: `grepai_search`, `grepai_trace_callers/callees`) — semantic
  search over a qdrant workspace. Use it when you don't know the right keyword
  to grep for and need to find code by describing what it does.
- **`grep` / `Read`** — when you already know the file or the exact string, or
  the change is docs-only. A literal match is often faster than formulating a
  semantic query. Don't run an index tool just to have run it.

Rules of thumb:

- Before editing an unfamiliar function/class/method, run
  `gitnexus_impact({target: "symbolName", direction: "upstream"})` and report
  HIGH/CRITICAL risk to the user before proceeding.
- Never rename symbols with find-and-replace; use `gitnexus_rename`.
- Run `gitnexus_detect_changes()` before committing code changes.

Never hand-edit `.grepai/config.yaml`. It is generated by `agent-code-intel`,
and a running GrepAI watcher rewrites that file from memory on every index —
manual edits are silently reverted, minutes or hours later, with nothing in any
log. Re-run `agent-code-intel --apply` instead.

### After every task that changes the codebase

Run `agent-code-intel --refresh` from the project root once the task is done
and before committing. It re-indexes GitNexus, starts the GrepAI watcher if it
isn't running, and audits both; it exits non-zero if either index is stale or
misconfigured.

need a refresh.
